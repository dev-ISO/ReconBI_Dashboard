# ReconDashboards 0.8.0 — Real sharing, permissions, undo/redo, activity log

Design contract for Wave 19. Both halves (backend packages and frontend packages)
implement exactly this wire contract; the PSV Valve Tracker host consumes 0.8.0
afterwards. Keep this file updated if implementation forces a deviation.

## Vocabulary (three distinct verbs)

- **Share** (collaborative): grant *named users* access to THE SAME dashboard,
  each with configurable permissions. Everyone sees the same document; the
  existing `expectedUpdatedAtUtc` optimistic-concurrency guard stays the
  collision handler.
- **Send** (copy): a HOST concern (the PSV tracker sends a snapshot through its
  chat feature; the recipient saves a copy they own). The library only
  guarantees `createDashboard` + the layout doc stay a stable snapshot format.
  No library work beyond not breaking this.
- **Publish** (legacy `IsShared` boolean): "visible to everyone". Retained
  unchanged for seeded system content; still gated by
  `ICurrentUserProvider.CanManageShared`. UI relabels it "Everyone".

## New tables (one new migration in ReconDashboards.Postgres)

```sql
CREATE TABLE rcd_dashboard_shares (
    "Id" integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    "DashboardId" integer NOT NULL REFERENCES rcd_dashboards ("Id") ON DELETE CASCADE,
    "UserId" character varying(128) NOT NULL,      -- opaque host id, same convention as OwnerUserId
    "CanEditLayout" boolean NOT NULL DEFAULT false, -- move/resize tiles, doc settings, slicer/text/image tiles
    "CanManagePages" boolean NOT NULL DEFAULT false,-- add/remove/rename/reorder/recolor pages
    "CanEditCharts" boolean NOT NULL DEFAULT false, -- add/remove tiles, edit chart specs/format
    "GrantedByUserId" character varying(128) NOT NULL,
    "CreatedAtUtc" timestamp NOT NULL,
    "UpdatedAtUtc" timestamp NOT NULL,
    UNIQUE ("DashboardId", "UserId"));
CREATE INDEX ON rcd_dashboard_shares ("UserId");

CREATE TABLE rcd_dashboard_activity (
    "Id" bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    "DashboardId" integer NOT NULL REFERENCES rcd_dashboards ("Id") ON DELETE CASCADE,
    "UserId" character varying(128) NOT NULL,
    "Action" character varying(64) NOT NULL,
    "DetailJson" jsonb NULL,
    "AtUtc" timestamp NOT NULL);
CREATE INDEX ON rcd_dashboard_activity ("DashboardId", "AtUtc" DESC);
```

All three permission flags false = **view-only** grant. Shares are
dashboard-only this wave (models keep owner + IsShared).

Activity retention: after insert, trim to the newest 500 rows per dashboard.
Actions: `created | saved | renamed | shared | unshared | shareChanged | left |
deleted | duplicated`. `DetailJson` carries the structured summary (below) or
`{ "targetUserIds": [...] }` for share actions.

## System (built-in, read-only) content

- New option `RcdOptions.SystemOwnerUserId`, default `"system"` (matches the
  PSV seeds).
- A dashboard/model whose `OwnerUserId == SystemOwnerUserId` is read-only for
  EVERYONE through the API — update/delete/share return 403
  `rcd.dashboard.system_readonly` / `rcd.model.system_readonly`, message:
  "This is a built-in item managed by the application. Make a copy to edit it."
  Seed scripts (raw SQL) remain the only writer.
- `duplicateDashboard` / `duplicateModel` must be allowed for **any user who
  can view** the item; the copy is owned by the caller, `IsShared=false`,
  name `"{name} (copy)"` de-duplicated (existing behavior).
- Summaries gain `isSystem: boolean` so UIs badge "Built-in" and swap
  Edit → "Make a copy".

## Access rules (DashboardService)

Visibility (list/get/query): owner OR publish (`IsShared`) OR a share row.

Save (`updateDashboard`):
- owner / `CanManageShared` admin: full edit (never on system rows).
- grantee: allowed only when the **computed change classes** are covered by
  their flags (differ below). Grantees may NOT change `name`, `description`,
  `modelId`, or `isShared` — reject with `rcd.dashboard.share_forbidden_fields`.
- publish-only viewer: 403.
- Insufficient grantee flags: 403 `rcd.dashboard.permission_denied`, message
  naming the missing class ("Your access does not allow page changes.", etc.).

Delete (`DELETE /dashboards/{id}`) — contextual:
- owner / admin (non-system): soft delete + activity `deleted`. Share rows kept
  (hidden anyway because visibility filters `IsDeleted`).
- caller has a share row and is NOT the owner: delete ONLY the caller's share
  row (this is "remove from my list"), activity `left`. 204.
- publish-only viewer: 403 `rcd.dashboard.forbidden`.

## Layout differ (Core) — one component, two consumers

`DashboardLayoutDiffer.Diff(oldDoc, newDoc)` → `LayoutChangeSummary`:
- class flags: `LayoutChanged` (tile move/resize, doc-level settings, slicer/
  text/image tile edits), `PagesChanged` (page add/remove/rename/reorder/color/
  mobile layout/drillthrough), `ChartsChanged` (tile add/remove, chart
  spec/format changes).
- detail: `pagesAdded[]`, `pagesRemoved[]`, `pagesRenamed[{from,to}]`,
  `tilesAdded`, `tilesRemoved`, `chartsModified[]` (titles), `settingsChanged`.
- Keyed by page id / tile id. Anything unrecognized ⇒ set ALL class flags
  (fail closed for permissions; log renders "updated the dashboard").

Consumers: (a) grantee save enforcement — map each raised class flag to the
required permission; (b) the `saved` activity `DetailJson`.

## Endpoints (AspNetCore, existing route prefix, `/v1`)

Policy slot changes: dashboard `update`, `delete`, `shares`, `leave`,
`activity` move to the **View** policy slot (service-level rights above are
authoritative — a grantee with edit permission may lack the host's author
capability). `create` / `duplicate` / all model writes stay **Author**.

New:
- `GET  dashboards/{id}/shares` → `{ shares: DashboardShare[] }` — owner/admin.
- `PUT  dashboards/{id}/shares` body `{ shares: [{ userId, canEditLayout,
  canManagePages, canEditCharts }] }` — REPLACES the full grant set (bulk
  multi-user apply); responds with the updated `{ shares: [...] }`. Owner/admin,
  non-system. Rejects the owner/caller as a target, empty ids and duplicate ids
  (`rcd.dashboard.share_target_invalid`). Writes ONE `shared` / `unshared` /
  `shareChanged` activity row per action kind, carrying the affected users in
  `DetailJson.targetUserIds` (not one row per user).
- `POST dashboards/{id}/leave` — removes the caller's share row (explicit form
  of the grantee delete path).
- `GET  dashboards/{id}/activity?limit=100&beforeId=` →
  `{ entries: ActivityEntry[] }` — owner/admin/grantees holding ANY edit flag.
  `limit` clamps to [1, 500].
  Note: "admin" throughout assumes the row is VISIBLE to the admin — the
  visibility rule (owner OR publish OR share row) has no admin bypass, so
  admins manage published/shared content, not private drafts.
- `GET  users?query=` → `RcdUser[]` — the share-picker directory (View policy).

## IUserDirectory (Core abstraction, host-implemented, optional)

```csharp
public interface IUserDirectory
{
    Task<IReadOnlyList<RcdUserInfo>> ListUsersAsync(string? query, CancellationToken ct);
    Task<IReadOnlyDictionary<string, RcdUserInfo>> ResolveAsync(
        IEnumerable<string> userIds, CancellationToken ct);
}
public sealed record RcdUserInfo(string UserId, string DisplayName, string? Email);
```

Default = `NullUserDirectory` (empty list; `Resolve` echoes ids as display
names) so existing hosts keep compiling/running; the Share dialog shows a
"user directory not configured" state. Demo host implements it over its demo
users. Document the seam in INTEGRATION.md (§2, next to ICurrentUserProvider).

## Undo/redo (dashboards-core `DashboardStore`)

- Edit-session history of document snapshots (`{ layout, activePageId }`):
  every mutating store method, while `mode === 'edit'`, pushes a
  `structuredClone` of the PRE-change state onto `undoStack` (cap 50) and
  clears `redoStack`.
- Coalescing: consecutive `applyLayout` calls within 400 ms collapse into one
  entry; consecutive `updateChart` for the same tile id within 800 ms likewise
  (FormatPanel slider storms).
- `undo()` / `redo()` swap through the stacks and restore; both set
  `dirty: true`. `canUndo` / `canRedo` exposed on state.
- History clears on `open` / `close` / `enterEdit` / `discardEdits`; it
  survives `save()` (you can undo past a save; the next save persists it).
- UI: toolbar Undo/Redo buttons (edit mode only) + Ctrl+Z / Ctrl+Y /
  Ctrl+Shift+Z on the DashboardView root, ignored when focus is in an
  input/textarea/select/contenteditable.

## UI work (dashboards-ui)

- **DashboardToolbar**: Share button (owner/admin, non-system) → ShareDialog;
  overflow menu: "Make a copy" (everyone), "Delete" (owner/admin, non-system)
  vs "Remove from my list" (grantee), "Activity" (edit-rights holders),
  "Linked model…" (owner/admin, edit mode — small picker writing `modelId`
  through the normal save path). New optional `extraActions?: ReactNode` prop
  so hosts can inject e.g. "Send to chat".
- **ShareDialog**: searchable multi-select user picker (GET users) with chips;
  per-user permission row — "Can view" / "Can edit" toggle, "Can edit"
  expanding the three granular checkboxes; bulk "apply to selected"; current
  shares listed with remove; Save issues one PUT. Admin-only "Everyone
  (publish)" toggle mapping to `isShared`.
- **ActivityPanel**: reverse-chron "«user» «did what» · «when ago»" with
  detail lines rendered from `LayoutChangeSummary` (pages added/removed,
  charts modified by title…), "Load more" via `beforeId`.
- **Built-in content**: "Built-in" badge; Edit affordances replaced by
  "Make a copy" for `isSystem` rows (dashboards AND models/ModelListPanel).
- **Permission-scoped edit mode**: `DashboardView` uses `myAccess` — hide/
  disable page add/remove/rename (needs `canManagePages`), chart builder/tile
  add/remove (needs `canEditCharts`), grid drag/resize + text/image/slicer
  editing (needs `canEditLayout`). Server enforcement remains authoritative.
- **DashboardListPanel**: sections "Mine" / "Shared with me" / "Everyone";
  share-count badge on owned rows.

## Frontend implementation notes (0.8.0) — minor deviations

- **"Everyone (publish)" toggle visibility**: the wire contract exposes no
  admin flag, so the ShareDialog shows the toggle to *owner-or-admin*
  (`myAccess.canEdit && !viaShare`), not admin-only; a non-admin owner's flip
  is refused server-side and surfaced inline. Flipping publish issues its own
  `updateDashboard` PUT (carrying the current in-memory layout).
- **Undo/redo across save**: history is not cleared on `save()` (per
  contract), but `save()` returns the store to view mode and `enterEdit`
  clears history — so in practice history spans one edit session.
- **Ctrl+Z/Y/Shift+Z**: listener is document-level, gated on the view's edit
  mode (key events don't reach a non-focused root element); inputs/textareas/
  selects/contenteditable are ignored.
- **`leave()`** (store) does not auto-close an open session on that dashboard;
  `DashboardView` exposes `onDeleted` so hosts navigate away (also new:
  `onOpenDashboard` for "Make a copy" and `extraActions` pass-through).
- **PUT shares response body** is ignored by the client (typed `void`); the
  dialog re-lists on next open. Backend may return 204 or the updated set.
